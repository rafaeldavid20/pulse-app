### Control view notifications (TES-368)

Runner profile and issue development views subscribe to authorized Firestore
counter documents, coalesce in-flight refreshes, and detach while hidden.
Opening, reconnecting or explicitly reloading reconciles once. Profile reads
trigger a device observation only on explicit refresh; a server notification
never triggers a second observation. The local freshness clock makes no cloud
calls, and a profile is applied only after its exact request-ID acknowledgement.

Deploy the coordinated backend rules and signal writers before this frontend.
The counters expose no operational payload; profile/job data remains behind its
existing permission-checked action. See backend `docs/runner-signals.md` for the
coordinated deployment and rollback procedure.
